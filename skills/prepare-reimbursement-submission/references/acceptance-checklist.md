# 报销提交验收清单

## 结构参考

使用用户确认的模板或已验收交付包作为结构参考，核对交付层级、人员编号、总 Excel、材料 ZIP、PDF 发票和图片附件的组织方式。不要把旧项目的姓名、银行账号、金额、路线或票据内容套用到新报销任务。

## 1. 输入与人员范围

- 已确认哪一份Excel是本次唯一模板。
- 已列出应保留、删除和新增的人员；Excel、文件夹、ZIP三处名单一致。
- 已列出每个人的原始出发地、最终目的地、实际行程、可报标准、付款人与共同付款关系。
- 身份、付款、发票、车票和票价截图逐项有来源；未知项保持“待确认”。
- 已删除用户明确不报销的人员和项目，例如地铁、超标部分或重复费用。

## 2. 目录与ZIP

- 正式交付根目录、最终Excel和最终ZIP均以 `《AAA》XX组Y人费用类型Z元` 为基础命名；项目、组别、人数、费用类别和金额均与本次工作簿核验结果一致，金额以最终 `报销金额` 合计为准。
- 根目录只有一份最终Excel、一份最终ZIP和材料文件夹。
- 人员文件夹按 `01姓名` 至 `NN姓名` 连续编号；共同住宿等费用放独立文件夹，避免在两个人文件夹中重复。
- 每个人文件夹只放与其报销有关的付款截图、PDF发票、车票或高铁二等座价格截图。
- 发票使用PDF原件；图片使用原文件，不生成低清压缩副本。
- ZIP目录结构与外部材料文件夹一致。
- 对ZIP内外文件做路径、大小和哈希比对：缺失、额外和哈希不一致均为零。
- ZIP不得包含 `.xlsx`、`.xls`、`.txt`、`.json`、脚本、临时文件或系统隐藏文件。
- 检查每份PDF以 `%PDF-` 开头并可正常打开；文件名路线、姓名和金额应与PDF内容一致。

## 3. Excel明细

- 保持模板工作表名称、列顺序、合并单元格、行高列宽、边框和打印设置。
- 明细人员编号连续；相同人员的合并区域完整，不覆盖相邻人员。
- 事由、日期、地点、交通工具、原费用和报销金额与票据逐行一致。
- 报销标准以高铁二等座价格为比较基准；转乘行程可逐段列票据，并按实际交通方式验收报销金额：
  - 对航空出行项目，汇总同一报销人从原始出发地到最终目的地的机票及同一行程必要接驳或转乘票据；实际交通费合计超过同一出行日期、非转乘高铁二等座最低价格时，整个项目按该最低价格封顶并附查询原图，未超过时按实际合计报销。
  - 普通火车票（硬座、硬卧、软卧、一等卧、高铁二等座及其他非动卧/高级软卧席别）逐张按实际支付金额实报实销，不例行做高铁最低价比较。国内通常不超过2000公里的普通软卧一般低于高铁二等座，按实际金额列报即可；路线、票价或席别显示可能超过标准时，才进入下一条核查。
  - 动卧、高级软卧或其他明确可能超过标准的火车票，查询同一出行日期、同一原始出发地至最终目的地、非转乘的高铁二等座最低价格；进行比较时附可辨识的价格查询原图，按实际票价与最低价两者较低值报销。若该票属于航空出行项目，仍需并入航空项目核算。
  - 其他交通方式或无法确认席别时标记“待确认”。
- 日期是数值日期，格式为 `yyyy-mm-dd`；逐行对照票面日期，不以订单日期、支付日期或到达次日替代。
- 明细正文沿用模板字体和字号；新增行不得残留Arial、默认Calibri或异常字号。合计单元格也必须复制相邻模板样式。
- `报销金额`列逐行求和正确；共同付款不能造成重复报销。
- 明细备注只写票据、金额和分摊的实际处理结论，不以“用户口径”或类似指令性措辞开头；根据票种灵活写明按实际金额报销、按高铁二等座最低价封顶、付款与票面差异或共同付款覆盖关系。

## 4. Excel附件

- 已完整执行 `evidence-provenance.md`：所有图片仅来自原始证据或确定性转换，未使用旧工作簿媒体作为证据源。
- 每份PDF均以经验证的本地确定性渲染器 `300 DPI / RGB / 整页` 逐页直接渲染，页数与PNG数一致，渲染后未做二次图像处理；若默认渲染器存在字体重叠、替代或缺字，必须记录并改用另一种经视觉核对合格的本地渲染器，否则失败关闭。
- PDF派生PNG只位于候选/返工目录的 `PDF转PNG` 下，保留原相对父目录；单页沿用原PDF stem，多页使用 `-第NNN页`，无通用页名。
- 已记录PDF与每页PNG的哈希、字节数、页数/页码、尺寸、渲染器/版本/参数、视觉可读性结论和最终工作表锚点。
- 付款截图放在付款截图列，发票页面图放在发票列，票价或标准参考放在参考列，不串列。
- 电子发票：PDF原件留在文件夹和ZIP；将PDF页面直接渲染成清晰图片嵌入Excel，不截取手机查看器界面。
- 付款和票价截图尽量使用原始像素文件；嵌入后保持纵横比、完整可读，不裁掉金额、日期、路线或付款对象。
- 共同付款截图可以在相关行重复引用，但文件夹中无需制造无意义副本；验收时说明覆盖了哪些人和哪些金额。
- 所有证据图片默认是“置于单元格上”的嵌入式 DrawingML Picture：使用内部媒体关系，无外部链接、`IMAGE()`公式或背景图；图片 `Placement=xlMoveAndSize`，不允许自由漂浮。只有接收方软件及版本明确支持并完成交付副本验证时，才允许使用目标单元格 `HasRichDataType=True` 的 rich-data 图片，并记录例外理由和接收环境。
- 插入图片前已启用工作簿图片不压缩设置；若当前 VBA/COM 版本提供 `DoNotCompressPictures` 则设为 `True`，否则以保存后的 `xl/workbook.xml` 为准并确认 `workbookPr` 为 `autoCompressPictures="0"`。该设置不能恢复已被压缩的旧图片，旧图片必须从原始文件重新插入。
- 图片锚定在对应证据单元格或合并区域，已记录左上、右下锚点；保持纵横比、完整可读、未裁切或重采样。原始 JPG/PNG 在 `xl/media/` 中保留原始字节时 SHA-256 必须一致；发生合法确定性重编码时，尺寸和解码后的像素必须等价。
- 已枚举最终XLSX的 `xl/media/`、`xl/drawings/*.xml`、关系文件及任何 `xl/richData/`：默认由 DrawingML 图片对象及内部关系追溯到原始栅格文件或 `PDF转PNG` 中具体页面，rich-data 例外由对应关系和目标单元格追溯。图片数量、载体、锚点和清单一致；存在无法映射媒体、外部链接或未经说明的图片载体时不得交付。
- 已完全关闭 Microsoft Excel，将最终XLSX复制为独立交付副本并重新打开，逐项确认全部图片显示正常；对代表性 DrawingML 图片直接选择、移动和缩放抽检，确认随单元格移动缩放，结束后不保存交互检查变更。如接收方软件及版本已知，还须在该环境打开交付副本；未做时明确标注接收端兼容性未验证。

## 5. 面单与公式

- 面单收款人、开户行和账号来自用户确认的信息，不从旧项目猜测。
- 费用用途应分开显示进组差旅费、住宿费等实际分类。
- 面单只显示金额大于 0 的费用项目内容；住宿、餐费等分项为 0 时，对应行的用途和金额均留空或不显示，保留模板中的序号，不删号、不重排，不写“本批无”，也不显示 `0`；面单总计仍须正确联动实际有金额的分项。
- 若沿用当前示例模板，检查：面单差旅分项取明细差旅行、住宿分项取住宿行、总计汇总所有分项；具体单元格以本次模板为准。
- 明细合计、面单分项、面单总计和人民币大写四者一致。
- 扫描 `#REF!`、`#DIV/0!`、`#N/A`、意外的 `#VALUE!` 和 `#NAME?`。区分真实公式错误与第三方工具对中文工作表名或单元格图片的不兼容。
- 用Microsoft Excel打开后确认公式重新计算、图片显示正常、日期不显示时间、打印区域没有裁切。

## 6. 最终交付门禁

- 正式交付目录的结构为连续编号的人员文件夹（以及已说明的共同费用文件夹）、一份 `《AAA》XX组Y人费用类型Z元_复核版.xlsx` 和一份 `《AAA》XX组Y人费用类型Z元_发票&付款截图_复核版.zip`；没有额外的候选、缓存、脚本、报告或预览文件。
- 每个人员文件夹都与工作簿中的实际报销人对应；文件夹内保留原始PDF发票、原始付款截图和该项目必需的原始支持材料。未知或不匹配证据仍为“待确认”，不得为了凑齐目录而补造或替换。
- 最终Excel已存在，已在完全关闭 Microsoft Excel 后从独立交付副本成功重新打开并确认全部图片可见；工作簿的人员、金额和附件映射与外部材料文件夹一致。接收方软件及版本已知时，还须记录该环境的实际打开结果。
- 最终ZIP已存在，只包含完整材料文件夹及其原始证据；ZIP内外路径、大小和SHA-256逐项一致，且不含Excel、临时文件、缓存、中间转换物、脚本、报告、预览或重复的非权威证据。
- 最终交付根目录可由财务直接复核：文件名、人员文件夹、工作簿和ZIP使用同一基础名称和同一人员范围，总额与 `报销金额` 合计一致。

## 7. 最终验收报告

交付前用简短报告列出：

- 最终人数及增删人员。
- 差旅费、住宿等分类金额和总金额。
- 每个人的报销小计，或至少列出异常和共同付款分摊。
- PDF数量、图片数量、ZIP内外哈希一致性。
- 日期、路线、金额、发票文件名等发现的问题及处理状态。
- Excel原生打开验证是否完成；未完成时必须明确标注，不得用结构检查冒充视觉验收。
- 原始证据处理前后哈希是否一致、PDF页数与渲染PNG数量是否一致、`xl/media/`是否全部可追溯。
- `xl/media/`、`xl/drawings/`和任何 `xl/richData/`中的图片数量、载体、左上/右下锚点和关系是否与清单一致；默认 DrawingML 图片是否全部嵌入、使用内部关系、随单元格移动缩放并可追溯；rich-data 例外是否记录接收环境、理由与实际打开结论。
- 报告中的金额、面单金额、明细合计和人民币大写是否来自同一份当前交付副本；旧版本金额、旧报告和历史检查结果是否已明确标识，未与当前结论混用。
- 明确确认未调用图像生成、AI重绘/重构、生成式填充、超分辨率、降噪锐化、合成文字或渲染后二次美化。

任何影响金额、人员、日期、票据对应关系或Excel图片显示的问题未解决时，只能标记为候选版，不得称为最终可提交版。
