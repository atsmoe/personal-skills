
# 报销提交标准

按用户提供的报销模板与本标准制作可直接提交的交付包。处理Excel时同时遵守可用的电子表格工作流；处理或转换发票时同时遵守可用的PDF工作流。

## 最终交付包与命名

最终可提交目录使用基础名称 `《AAA》XX组Y人费用类型Z元`：`AAA` 是项目名，`XX组` 是实际部门/组别，`Y人` 是本次实际覆盖人数，`费用类型` 使用实际费用类别（不固定为差旅费），`Z元` 是已核验的最终报销总额。总额以 `报销金额` 列及面单联动结果为准；不要猜测项目、组别、人数、费用类别或金额。金额有小数时保留必要小数，例如 `4829元` 或 `4829.50元`。

经用户确认整理正式交付目录时，目录内必须能够直接交由财务复核，且只包含以下交付项：

```text
《AAA》XX组Y人费用类型Z元/
├── 01姓名/
├── 02姓名/
├── …（连续编号的其他人员或已说明的共同费用文件夹）
├── 《AAA》XX组Y人费用类型Z元_复核版.xlsx
└── 《AAA》XX组Y人费用类型Z元_发票&付款截图_复核版.zip
```

人员文件夹与工作簿记录一致，保存原始PDF发票、原始付款截图和必要的原始支持材料。ZIP 是这些材料文件夹的完整证据归档，目录和文件须与外部材料文件夹逐项一致；不放 Excel、缓存、临时文件、转换中间物、脚本、验证报告或重复的非权威证据。候选/返工目录仍与正式交付目录分离，未经用户明确同意不得把候选版称为正式提交包。

## 不可变规则

- 先只读检查用户指定模板；模板是版式、合并单元格、打印设置和公式关系的唯一来源，不另造版式。
- 报销证据图片只能来自原始文件，或来自原始文件的确定性格式转换；旧Excel中的嵌入图片只能作为布局参考，不能作为证据来源。
- PDF证据须通过经验证的本地确定性渲染器直接渲染：固定 300 DPI、RGB、整页、无裁切，每页输出一张 PNG。默认可用 PyMuPDF/MuPDF；若其输出出现字体替代、文字重叠、缺字或其他与原票据不一致的可读性问题，可改用另一种普通本地渲染器，但必须记录原因、工具及版本、命令参数和视觉核对结果。没有可忠实呈现的确定性输出时，该 PDF 必须失败关闭，不得用阅读器界面截图、AI 修复或手工重绘替代。
- PDF转PNG必须写入本次候选/返工目录下的 `PDF转PNG` 子目录，并保留原PDF的相对父目录。单页命名为 `<原PDF文件名不含扩展名>.png`；多页命名为 `<原PDF文件名不含扩展名>-第001页.png`、`-第002页.png` 等，不得使用 `page-001.png` 一类丢失源文件名的名称。
- 严禁用图像生成、AI重绘或文档重构、生成式填充、AI放大/超分辨率、改变证据像素的降噪锐化、合成文字、人工补造缺失票据内容或渲染后二次美化来制作报销证据。OCR/视觉只能提取姓名、金额、日期、路线等元数据，不能反向重建嵌入Excel的票据图片。
- 原始PNG/JPG/JPEG等栅格证据应尽量按原始字节直接用于Excel；确需兼容性转换时，记录源哈希、转换工具、输出哈希及尺寸，且不得使用生成式处理。
- Excel中的每张报销证据默认使用 Microsoft Excel 的“置于单元格上（Place over Cells）”嵌入式 DrawingML Picture。使用 `Shapes.AddPicture()` 或等价方式时必须设置 `LinkToFile=False`、`SaveWithDocument=True`，不得引用本机或网络路径；插入前应启用工作簿图片不压缩选项，若当前 VBA/COM 版本提供 `DoNotCompressPictures` 则设为 `True`，否则以保存后的 XLSX `workbookPr` 为准并确保 `autoCompressPictures="0"`。图片必须锚定到正确费用行的目标单元格或合并区域，设置 `Placement=xlMoveAndSize`，并记录左上、右下锚点。图片应保持纵横比、在目标区域内居中并留少量边距，完整展示证据，不裁切、不重采样、不压缩；对原始 JPG/PNG 应尽量保持源字节不变。图片不压缩设置不能恢复已经压缩的旧图片，旧图片必须从原图重新插入。`IMAGE()` 公式、工作表背景和阅读器截图都不可作为证据图片。
- 只有接收方软件及版本明确支持、且交付副本已在该环境重新打开验证时，才允许使用 `Range.InsertPictureInCell()` 插入的“置于单元格中（Place in Cell）”rich-data 图片。必须在差异报告中记录接收环境、所用单元格、`HasRichDataType`、媒体验证和实际打开结果；不得仅因制作端可见就推定接收端兼容。
- 每次制作都建立来源清单：记录原文件相对路径、类型、SHA-256、字节数；PDF另记录页数、PyMuPDF与MuPDF版本、固定渲染参数以及每页PNG的页码、相对路径、SHA-256和尺寸；再记录人员/费用行及最终工作表图片锚点。
- 保存Excel后必须检查 XLSX ZIP 容器中的 `xl/media/`、`xl/drawings/*.xml`、对应关系文件和任何 `xl/richData/`：把每个媒体映射回获准的原始栅格文件或 `PDF转PNG` 页面，并追溯到原 PDF 及页码。默认方案必须确认每张证据都是嵌入式 DrawingML Picture、使用内部媒体关系、左上/右下锚点正确并随单元格移动缩放；rich-data 例外则确认目标单元格 `HasRichDataType=True`。所有方案都必须确认没有外部链接。插入保留字节时核对 SHA-256；Excel或合法库发生确定性重编码时，核对来源、尺寸、输出哈希及解码后的像素等价性。任何媒体无法追溯、被压缩、或图片载体与清单不一致时，结果只能是候选版，不能交付。
- 根目录只保留一份按上述基础名称命名的总报销Excel、一份对应材料ZIP，以及按人员或共同费用分类的材料文件夹；不要给每个人制作Excel。
- ZIP只放材料文件夹的完整原始证据归档。不得包含Excel、TXT、JSON、脚本、验证报告、预览、缓存或无必要的中间转换文件。
- ZIP中的发票必须保留为有效PDF；Excel里的发票栏应嵌入由原PDF页面直接转换的清晰图片，不使用手机查看器截图代替发票页面。
- 付款截图、票价截图使用用户提供或查询取得的原图，避免重采样和有损压缩。共同付款可映射到多条明细，但必须核对人员、总额与分摊关系。
- 交通费报销标准以高铁二等座价格为比较基准，并按实际交通方式分别判断：
  - 机票：以同一报销人从原始出发地到最终目的地的航空出行项目实际交通费合计，与同一出行日期、非转乘高铁二等座最低价格比较；同一行程必要的接驳或转乘票据计入该项目。实际合计超过最低价时，该项目按最低价封顶，否则按实际合计报销。Excel中同时保留机票票据、付款截图及可辨识路线、日期、席别和最低价格的查询原图。
  - 普通火车票（硬座、硬卧、软卧、一等卧、高铁二等座及其他非动卧/高级软卧席别）：逐张票据按实际支付金额实报实销，不例行查询高铁二等座价格。国内通常不超过2000公里的普通软卧一般低于高铁二等座，按实际金额列报即可；如路线、票价或席别显示可能超过标准，再按下一条处理。若该票是航空出行项目的接驳或转乘票，仍需并入该航空项目核算。
  - 动卧或高级软卧，或其他明确可能超过标准的火车票：查询同一出行日期、同一原始出发地至最终目的地、非转乘的高铁二等座最低价格；只有进行该比较时才附可辨识的价格查询原图。实际票价不超过最低价时按实际金额报销，超过时按最低价封顶。
  - 其他交通方式或无法确认席别时，不自行套用上述规则，列为待确认。
- 日期必须是Excel真实日期，显示为 `yyyy-mm-dd`，不得显示 `00:00:00`，并与票面乘车日期一致。
- `报销金额`列是最终合计依据。面单分项、总额、人民币大写和明细合计必须联动一致。
- 面单只显示金额大于 0 的费用项目内容；住宿、餐费等分项金额为 0 时，面单对应行的用途和金额均留空或不显示，保留模板中的序号，不删号、不重排，不写“本批无”，也不显示 `0`。明细可保留必要的结构或零金额记录，但不得把零金额项目显示或联动为面单分项。
- 明细备注只写与票据和金额有关的实际处理结论，不以“用户口径”或类似指令性措辞开头，不重复用户要求。可根据实际情况写明“普通软卧，按实际支付金额报销”“动卧，附高铁二等座最低价截图并按较低金额报销”“付款截图与票面金额不一致，按票面金额列报”“共同付款，覆盖相关人员，按对应票据金额列报”等简短说明，并随票种、金额和分摊关系灵活调整。
- 未获确认的人员、费用、票据或分摊不得擅自补全；保留为“待确认”或明确列为阻塞项。不得用不匹配的发票顶替。
- 所有变更先在候选目录完成并验收；只有用户明确同意后才覆盖或整理正式交付目录。

## 工作方式

1. 盘点模板、人员、路线、票据、付款截图、票价截图与增删指令，建立逐人逐行映射。
2. 先完成明细数据与金额，再把附件默认作为锚定目标单元格区域的嵌入式 DrawingML 图片置于单元格上；只有接收环境已确认兼容时才使用原生单元格图片。共同付款、共同住宿等单独记录其归属和分摊。
3. 人员文件夹使用 `01姓名`、`02姓名` 的连续编号；共同费用可使用 `住宿` 等独立文件夹。文件名优先使用 `姓名-金额-路线.pdf` 等可人工核对的名称。
4. 生成总Excel和ZIP后，执行结构、金额、日期、附件、PDF、哈希与视觉验收。
5. 最终报告必须说明人员范围、金额分解、材料数量、异常项、PDF渲染器与可读性结论、`xl/media`/`xl/drawings`/任何 `xl/richData` 的追溯结果、图片载体、锚点、外链状态，以及是否在完全关闭 Excel 后从独立交付副本重新打开并验证全部图片可见。报告金额、面单金额、明细合计和人民币大写必须来自同一份当前交付副本；旧版本金额、旧报告和历史检查结果必须明确标识，不得混入当前验收结论。默认 DrawingML 图片还要记录 `xlMoveAndSize` 和代表性图片的直接选择、移动、缩放抽检；如接收方软件及版本已知，记录该环境的实际打开结果，否则明确标注接收端兼容性未验证。

进行制作或验收时，完整读取并逐项执行 [acceptance-checklist.md](acceptance-checklist.md)。制作含PDF证据的Excel时，还必须完整读取并执行 [evidence-provenance.md](evidence-provenance.md)；优先复用 [../scripts/render_pdf_evidence.py](../scripts/render_pdf_evidence.py) 生成确定性PNG及基础渲染清单。
