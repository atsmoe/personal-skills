# 报销证据来源与PDF渲染规则

## 1. 证据边界

- 权威输入仅限用户提供的原始PDF和原始栅格图片。旧Excel的 `xl/media/`、手机查看器截图、OCR文字和预览图都不是权威证据源。
- 原始证据目录只读。新生成的PNG、清单、预览或临时文件不得写回原始目录。
- 若原文件损坏、加密、缺页、方向异常或不可读，记录异常并请求补件；不得生成、修复或重构缺失内容。
- 不调用图像生成工具，不使用AI重绘、文档重构、修复、填充、超分辨率、降噪、锐化、背景净化、合成文字或任何改变证据像素的美化流程。
- OCR/视觉仅可用于读取或分类元数据；它的输出不能成为Excel中证据图片的像素来源。

## 2. PDF到PNG的确定性标准路径

默认使用 PyMuPDF/MuPDF 和以下固定调用：

```python
import pymupdf

pix = page.get_pixmap(
    dpi=300,
    colorspace=pymupdf.csRGB,
    alpha=False,
    annots=True,
)
pix.save(output_png)
```

固定语义：

- `dpi=300`
- `colorspace=pymupdf.csRGB`
- `alpha=False`
- `annots=True`
- 输出PNG
- 原PDF每页恰好一张PNG，保持原页顺序与方向
- 渲染后不再进行任何图像处理
- 若默认输出出现字体重叠、替代、缺字或其他可读性异常，记录异常并可改用另一种普通本地确定性渲染器；必须固定版本和参数，并对同一页进行视觉核对
- 若没有可忠实呈现的确定性输出，失败关闭；不得使用阅读器界面截图、AI修复或手工重绘

输出必须位于 `<候选或返工目录>\PDF转PNG\<原相对父目录>\`：

- 单页：`原文件名.pdf` -> `原文件名.png`
- 多页：`原文件名.pdf` -> `原文件名-第001页.png`、`原文件名-第002页.png`……

不得把输出命名为通用的 `page-001.png`，不得丢失原PDF文件名，也不得把PNG写回原证据文件夹。

铁路客票子流程可先把原 PDF 按已核实字段复制改名，再渲染该字节一致的副本；此时 PNG 跟随副本名称，仍放在候选目录的 `PDF转PNG` 中。来源清单须同时记录原始相对路径及哈希、改名副本及哈希和每页 PNG；副本哈希必须与原件一致。改名不允许重建 PDF 或省略原件映射。

## 3. 渲染记录

渲染前后至少记录：

- 原PDF相对路径、SHA-256、字节数、页数
- 渲染器名称、版本和可执行文件路径；PyMuPDF时另记 `pymupdf.__version__`（如可用）、`pymupdf.VersionBind`、`pymupdf.VersionFitz`
- 固定参数 `300 DPI / RGB / 整页`，以及渲染器专属参数
- 每份PDF的视觉可读性核对结论和任何渲染器例外原因
- 每页的人类可读页码、输出相对路径、PNG SHA-256、字节数、宽度和高度
- 对应人员、费用明细行、工作表名称及最终图片单元格/锚点

技能附带的 `scripts/render_pdf_evidence.py` 负责批量渲染并生成基础JSON；人员、明细行和Excel锚点可在后续总来源清单中补充。

脚本要求新的候选目录，清单必须位于候选目录内；不允许写回原件目录或覆盖已有结果。渲染前检查文件、页数及像素预算，限制与跨设备参数见 [railway-tickets.md](railway-tickets.md) 的输入与输出保护。输入超限应分批，不自动关闭限制。

## 4. 原始栅格图片

- PNG/JPG/JPEG等优先直接按原始文件字节插入Excel。
- 若软件兼容性要求确定性转换，必须记录源哈希、工具与版本、输出哈希、源/输出尺寸和像素等价检查；禁止生成式转换。
- Excel中的缩放只改变展示尺寸，不得裁掉金额、日期、路线、付款对象、发票号码等证据字段。

## 5. Excel嵌入图片与媒体追溯

保存工作簿后，把 `.xlsx` 作为ZIP检查：

1. 枚举 `xl/media/` 的所有文件及SHA-256、尺寸。
2. 枚举 `xl/drawings/*.xml`、相关关系文件和任何 `xl/richData/`；默认确认每张证据由 DrawingML `pic` 图片对象通过内部关系引用，并记录工作表、左上和右下锚点。图片必须使用随单元格移动缩放的锚定语义，不得自由漂浮。只有接收方软件及版本明确支持并完成交付副本验证时，才允许使用原生单元格图片（`HasRichDataType=True`），并记录目标单元格和接收环境。
3. 检查插入和保存前已启用工作簿图片不压缩选项；若当前 VBA/COM 版本提供 `DoNotCompressPictures` 则设为 `True`，否则以保存后的 `xl/workbook.xml` 为准并确认 `workbookPr` 为 `autoCompressPictures="0"`。该设置不能恢复已经压缩的旧图片，发现旧媒体已压缩时必须从原始证据重新插入。
4. 把每个媒体文件映射到获准的源图片；PDF派生媒体必须先映射到 `PDF转PNG` 中具体页面，再映射到原PDF和页码。
5. 原字节被保留时要求SHA-256完全相同；Excel或合法库发生确定性重编码时，要求尺寸一致，并用解码后的RGB像素摘要或其他确定性方法证明像素等价。
6. 确认没有 `IMAGE()`公式、工作表背景或外链；默认 DrawingML 图片必须嵌入工作簿、保持纵横比、完整展示，并锚定到正确单元格或合并区域。原始栅格图片应尽量保留源字节；如 Excel 或合法库发生确定性重编码，必须证明解码后的像素等价。
7. 任一媒体无法追溯、页数不匹配、发现旧工作簿媒体被当作源、图片被压缩或载体不符合清单时，立即失败关闭。

默认 DrawingML 图片的验收语义：图片可直接选中并出现缩放控制点，通过内部关系嵌入工作簿；左上、右下锚点对应正确证据区域，随单元格移动和缩放；打开工作簿后图像完整显示、没有外链或压缩，且 XLSX 关系和媒体哈希或像素等价结果可追溯。rich-data 例外的验收语义：正确单元格 `HasRichDataType=True`，并已在明确记录的接收软件及版本中从交付副本成功显示。

在 Microsoft Excel 中抽检时，先完全关闭工作簿，将最终XLSX复制为独立交付副本，再打开副本逐项验证全部图片显示和工作簿可保存性；对代表性 DrawingML 图片执行选择、移动、放大和缩小检查，确认其随单元格移动缩放，结束后不保存交互变更。如接收方软件及版本已知，还须在该环境打开交付副本；未做时明确标注接收端兼容性未验证。rich-data 例外另检查目标单元格类型。

## 6. 交付报告

报告至少说明：源/输出目录、PDF转PNG目录、工具与版本、固定参数、可读性结论、文件名映射、源文件/页/PNG/嵌入图片数量、原始文件未变化验证、`xl/media/`、`xl/drawings/`与任何 `xl/richData/` 的映射结果、默认 DrawingML 图片数量及左上/右下锚点、`xlMoveAndSize`、外链状态、交付副本打开结果、rich-data 例外数量与接收环境、异常项，以及未使用任何生成式图像工具或AI图像变换的确认。
