# 增量处理与上下文控制

目标是减少交给模型的重复资料；全表程序检查与必要的原图核对照常进行。不承诺固定 token 降幅。

## 先摘要，再展开

取得最新主表。在线有版本标识时检查版本；没有时获取最新导出到辅助目录，由本地程序比较。不能把文件时间戳、累计相同、最后一行相同或旧导出当作历史内容未变的证明。

运行技能目录中的脚本（`python` 代指当前环境可用 Python，脚本只依赖标准库）：

```text
python scripts/ledger_context.py --workbook <最新xlsx> --day <本次日期目录> --output <当天.work目录/context_before.json>
python scripts/ledger_context.py --workbook <最新xlsx> --day <本次日期目录> --baseline <上次context_after.json> --output <当天.work目录/context_before.json>
```

默认只输出末尾四行、汇总、变动范围与最多八项来源变化。全部差异保存在 `--output`，需要时按范围提取，不把整份状态再打印。可用 `--sheet` 指定工作表。导出文件名每次不同但指向同一在线工作表时，用稳定的 `--source-id`（文档 ID + 子表 ID）匹配；此 ID 不验证导出新鲜度。首次使用先运行 `--help`，无需读取脚本全文。

脚本只观察，不改工作簿、不访问网络、不读图片像素、不生成“已核实”标记。工作簿用内容 SHA-256，行签名解析文本/公式/缓存值，布局签名覆盖样式、尺寸、合并、图像与关系；照片比较 SHA-256 和 CreationTime。排序或插行会保守地扩大变化范围。布局变化不意味着需要重识别所有收据。

## 识别结果复用条件

在原有当天 `data.json` 或独立核对记录中保存：原图路径及 SHA-256、采购组与照片关系、实际核实字段、未解决项，以及写入/验收时的工作表和区域。不要为了加元数据重写原始票面内容。

- **可复用**：有实际看原图并核实的记录；源图哈希一致；对应当前表格内容及照片映射没有变化。日常追加时，历史图只保留引用。
- **局部重查**：原图变更、CreationTime/采购组配对改变、在线历史行改动、行插删后区域失配、缓存字段未核实，或用户明确要求复核。日期合并和共用照片有联动时，扩到完整采购组。
- **基线缺失/不兼容**：重新扫描当前表建立观察快照；本次日期中没有核实依据的图片须看原图。不要默认为全月重新识别，也不能认定旧 JSON 正确。
- **金额/结构异常**：程序先定位公式引用、日期块或样式；确实需要视觉判断时再加载历史原图。全月核对按用户要求执行，仍分日期分组读图并保存结果。

`context_before/after.json` 是观察快照，不是识别缓存或验收证书。不能把生成快照等同于已识图、已入账或已核对。没有可信来源记录时，照片未变也不能跳过用户要求的核对。

## 工具输出与图片

- 计算、重复检查、哈希/样式/图片锚点检查在程序内完成；返回结论、异常坐标及少量必要上下文。若截断，注明剩余结果路径；未输出不等于不存在。
- MCP 如只能全量读，在执行环境中保存/筛选原响应，再返回必要结果。不要打印整表 JSON、全部样式、完整日志、图片 base64 或全部工具定义；只发现本次所需工具。复用可靠脚本，避免每轮重写相同检查程序。
- 先看本次采购组概览，再读原图或疑点裁剪。物品照须可辨认物品和标签；收据小字、单位、小数点、数量及单价保持足够清晰，不能用低清缩略图直接定金额。原图不改，裁剪留辅助目录。
- 文件引用、Files API 上传或压缩 JPEG 不自动等于免视觉 token；模型实际收到的文字、图片和工具结果才是上下文。具体图像 token、缓存折扣由服务端决定，不在 skill 硬编码比例。
- 长任务把已确认决定、未解决项、来源路径和当前版本写进当天工作记录；接续时结合最新状态恢复，不反复粘贴完整聊天和全月证据。

## 验收范围

日常追加仍做全表程序核验，检查历史数据保留、汇总口径、统一行高和受影响图片几何。多人在线时保留检查以写前最新状态为基线，区分他人并发变动与本次写入，不回滚他人内容；具体流程见 [online-workbook.md](online-workbook.md)。覆盖本地来源并按 [reconciliation.md](reconciliation.md) 列出本次范围内的在线额外条目，不能把无本地来源当作应删除记录。视觉预览本次采购组、受影响合并区及末尾；标题/表头仅首次建模板、实际改变或异常时复查。格式修复不触发收据全量 OCR。在线和本地分别记录完成状态，未通过在线读回不能记为同步成功。
