# 在线采购表同步与验收

> 规范版本：v2.4.0

仅在用户要求在线创建、更新或核验时加载。目标文档及主表关系来自当前任务/项目配置；技能不内置在线文档 ID，不根据同名文件或旧项目推断。同步正式本地表前备份。两版存在金额/内容冲突时先做独立核对，再说明具体差异并确定处理口径。

## 多人实时协作

完成标准是手里的采购全部有匹配记录，其他人的增补保留并另列本次范围内的额外条目；本地未找到来源不表示记录应删除，也不能据此判断修改人。在线为主且需要本地镜像时，镜像包含读取时他人内容，记录读取时间/版本，不声称始终实时一致。

- 写前刷新版本和目标区域；无版本时重新读取/取得最新导出并程序比较。旧行号、旧汇总或本地表不能直接覆盖在线，也不修改他人编辑权限。
- 新增、插删行或历史修改纳入基线，重定位采购组与缺项。他人已补入同笔采购不重复新增；同名/同额不能单独证明相同采购，匹配见 [reconciliation.md](reconciliation.md)。
- 支持版本条件写入时使用冲突检查；否则小范围写后紧接读回。目标持续变化或定位不可靠时停止该区域写入、报告冲突并继续独立核对，不声称读后写消除全部并发风险。
- 只补授权缺项和必要汇总引用。核对请求不自动授权改价格或补账。格式修改依据最新样式，保留历史底色、照片及日期归属。
- 写后核验覆盖、额外条目与汇总。验收中出现他人编辑时区分与本次范围的关系，不回滚整表。

## 数据与格式

日常只写新增/变化/缺失区域；统一格式是结果约束，不要求每次重写全表。程序检查全表，模型只接收异常。只能全量读取的平台，在执行环境处理最新导出，不把整表 JSON、图片或完整样式交给模型。

同步前读取实际表头、列映射、合并、样式、尺寸和照片关系；粘贴值或 CSV 不证明格式同步成功。

| 项目 | 要求 |
|---|---|
| 照片 | 在实际照片列保留采购组对应合并；多行共用照合并完整明细区域，不仅放首格、不重复插图；不跨组/日期/汇总。 |
| 图片几何 | 按完整单格/合并区等比居中，沿用配置留白；在统一明细高度内缩放，不单独拉高有图行；平台图片模式有差异时适配并预览。 |
| 标题与汇总 | 保留主表真实合并及对齐，引用最新明细，累计不重复计入小结。 |
| 字体与对齐 | 按当前用户/模板的字体、字号、加粗、对齐及换行基准统一，不套用其他项目字体。 |
| 边框与尺寸 | 新增格带真实边框，历史底色/列宽保留；按当前基准统一明细高度，表头/标题/汇总分别沿模板。在线行高的下限与单位以当前项目/平台为准。 |
| 日期与金额 | 保留日期类型/显示格式与金额精度，数值仍为数字；数量不擅自舍入。 |
| 手动调整 | 保留用户已确认采购的日期归属及位置，不根据票面跨日移动/删除/重新排序；小结与累计包含实际归属采购。 |

pt、px 或平台尺寸单位不同时通过最新导出和预览换算，不能照抄数值。字体不支持时说明替代并核验尺寸；界面缩放、主题和网格线差异不是内容格式证据。

## 读回与验收

1. 读回真实照片、标题、汇总合并范围；接口不能返回时通过当前可用界面检查，截图不能证明隐藏合并关系。
2. 比较本次涉及区域的字体、对齐、换行、边框、日期/金额格式与配置尺寸；有全局统一要求时程序检查全表异常。
3. 预览新增区域、受影响多行照片与末尾，确认图片清楚、居中、无越界，文字及金额完整。
4. 通过样式读回或最新导出确认生效；检查接口字段整体替换行为，不把字段丢失直接归因于缓存。
5. 授权目标内差异修复后读回。权限/平台能力不足时列出未完成项；本地 XLSX 通过不代表在线格式通过。

`check_xlsx.py` 不比较两版合并/样式，不覆盖全部图片模式，不能单独作为在线验收依据。

## 腾讯文档接口适配

`set_cell_style` 在部分端点会重置省略字段。当前端点先看能力说明及实际样式读回；需要整体替换时保存快照，生成包含背景、字体/字号/颜色、加粗/斜体/删除线/下划线、水平/垂直对齐、换行及数字格式的完整样式块。边框通过相应接口设置；相同样式合并连续矩形批量写入，错误时只恢复本次受影响样式。

行高声明单位与实际可能不符：在96 DPI换算中120 px对应90 pt，需看当前原生导出和预览，不能把该数字当所有文档的固定要求。仅改字体/底色时不重写行高或照片。

恢复颜色只处理记录证明由本次助手新增的区域；历史颜色保留。没有单元格修改历史时无法确认标色人，不能用文档最后修改人推断。
