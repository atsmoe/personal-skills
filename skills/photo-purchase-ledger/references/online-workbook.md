# 在线采购表格式同步与验收

> **规范版本**：`v2.3.1`（2026-10-09）

仅在用户要求创建、更新或核验在线采购表时使用。本项目已明确在线表为主，本地表跟随在线采购内容和用户手动归属；同步本地前备份正式文件。其他项目按用户指定主表，未指定时以最新正式本地 Excel 为基准。先读取目标在线表，保留其中的用户改动，不能仅凭同名文件判断其内容与本地一致。若两边有会影响采购数据或金额的冲突，先完成不依赖冲突的核对，再指出具体单元格和差异。

## 多人实时协作

本项目完成标准是：我们手里的采购来源均有匹配记录，其他人的在线增补保留，并单独列出本地未找到对应来源的在线条目。不是将在线内容缩减到本地照片能证明的范围。本地镜像跟随本次读取的最新在线状态，包含他人增补；记录读取时间或版本，不声称本地始终实时一致。

- 写入前刷新在线版本及本次目标区域；版本不可用时重新读取或取得最新导出，程序比较变动。不能沿用旧行号、旧小结/累计或旧本地表直接覆盖在线，也不为同步整表锁定他人编辑权限。
- 若出现新条目、历史修改或插删行，先将其纳入基线，重新定位采购组、缺项与汇总公式；他人已补入的同笔采购不重复新增。同名或同额不能单独证明同一笔，匹配依据见 [reconciliation.md](reconciliation.md)。无关区域变化无需重查全月图片。
- 工具支持版本条件写入时使用其冲突检查；不支持时采用小范围写入、紧接读回。若本次区域持续变化或无法可靠定位，停止对该区域写入并报告冲突，继续可独立完成的核对。不声称读后写能排除所有并发冲突。
- 只补已授权的缺项与必要的汇总引用，金额按最新在线全部明细计算，保留他人条目。核对请求本身不授权修改数量/价格差异或补账。格式更新同样基于最新样式，保留历史底色和照片。
- 写后读回采购覆盖、额外条目和汇总，说明仍未匹配或存在差异的本地来源；额外条目清单按 reconciliation 参考交付。验收期间出现他人改动时，先辨别其与本次写入范围的关系，不能把在线变化一概算作助手损坏并回滚整表。

## 格式对应

日常同步先比较最新在线数据/样式与本次授权改动，只写新增、变更或缺失的区域。全局格式要求是结果约束，不要求每次将全表样式再写一次；全表一致性在程序内检查，模型只看异常范围。无法局部读取时可在执行环境处理最新全量导出，但不把完整表格或图片传回模型。快照、缓存失效和输出限制见 [incremental.md](incremental.md)。

导入前读取主表实际单元格格式、合并范围、行高列宽、图片锚点与采购组关系。使用平台提供的导入、样式、合并和图片能力完成同步；粘贴值或 CSV 不能作为完成格式同步的依据。在线表缺少的合并与样式应在导入后补齐。

| 项目 | 要求 |
|---|---|
| 照片区域 | 保留主表 J 列的实际合并范围。同笔多条明细共用一张照片时，纵向合并完整的明细行；仅放在首行、重复插图或将缩略图逐行排列均不算完成。多张照片沿用主表排列，不能漏图。合并不跨采购组、日期、小结或总计。 |
| 图片位置与大小 | 使用整个单格或合并区域进行等比缩放和双向居中，沿用本地照片的对应关系与留白。在统一明细行高及原表列宽内缩放图片，使图片可辨认、不遮挡边框、不串行，不能单独拉高有图行或缩矮无图行；若平台的格内图片模式不能跨合并区域，采用平台支持的浮动图片等适配方式并预览确认。 |
| 标题与汇总 | 保留标题和小结、总计的实际合并范围及对齐方式。例如主表标题合并 A1:J1 并居中时，在线表也应如此，不能只把标题写入 A1。不要把示例范围当成固定范围。 |
| 字体与对齐 | 本项目全表宋体、黑色；正文/表头/汇总 12 pt，标题 16 pt，标题/表头/汇总加粗、正文不加粗。**全表全局水平居中与垂直居中**：所有单元格（表头、明细、小结及总计）均强制设置水平居中（center）与垂直居中（center）；**全表全局开启自动换行（wrap text）**，确保规格型号、物料名称及备注完整展示不截断。单价（G列）和金额/汇总（H列）强制保留两位小数格式（`0.00`），避免因在线默认格式变为无小数位。 |
| 边框及尺寸 | 明细及汇总统一黑色细实线真实边框，新增格同样带边框。保留列宽和历史底色；新增明细及汇总默认白底，不自行加色。采购明细全表使用同一个固定行高，包括无图行、历史明细和照片合并区域内的各行。本项目明细、表头、小结和总计当前统一为在线 **120 px / Excel 90 pt**；在线明细至少 120 px。标题保留实际高度；其他项目沿用用户确认基准。主表原有参差行高须按该基准统一。编辑器网格线不能替代边框；规格等换行文字应完整显示。 |
| 日期与金额 | 日期保持日期类型及 `yyyy-mm-dd` 显示。单价沿用 `0.00`，合价和汇总沿用主表金额格式，不能因在线默认格式变成无小数位显示。数量保留原精度。数值仍是数字，不能用文本模拟格式。 |
| 公式与数据 | 保留明细计算、当天小结和累计公式的逻辑，核验在线计算结果及引用范围，不重复计入小结。照片合并不改变材料、数量或金额列。**绝对保留用户在在线端手动调整的条目**：若用户在特定日期手工插入、调整或归属了采购条目（例如用户在 10.3 增加了集装箱压机 23,500 元、在 10.4 增加了透明玻璃胶 20 元等），即使与原始收据票面日期不完全吻合，也**绝对严禁擅自以收据日期为由将条目回退、跨日移动、删除或重新排序**；对应小结与累计公式纳入口径，不得覆盖或清除用户已调整的小结金额。 |

平台的列宽、行高或图片尺寸单位与 Excel 不同时，按可见尺寸换算并通过预览调整，不能照抄数值。字体不支持时选可用的接近字体并说明实际替代。界面主题、工具栏、系统缩放和编辑器网格线差异不属于表格内容格式，不能仅凭截图显示密度认定行高错误。

## 上传或修改后的验收

1. 读回在线表，逐项比较标题、照片、小结和总计的实际合并范围。重点确认多行共用照片的 J 列仍是合并区域，而非首行单格放图。若平台无法返回合并信息，使用可操作的界面检查；截图只能辅助判断，不能据此证明隐藏的合并范围一致。
2. 检查本次涉及区域的字体与对齐、边框、列宽、换行、日期及金额显示格式，并核验所有上传照片的来源、数量和对应区域。确认全表已统一应用**水平居中、垂直居中及自动换行**；单价与金额列保留两位小数 `0.00`；本项目明细、表头、小结和总计均核验为在线 120 px / Excel 90 pt，标题核验实际高度。
3. 预览新增区域、受影响的多行照片及末尾汇总；标题和表头在首次建立、实际改变或异常时复查。在接近的缩放比例下比较布局，确认图片清晰、居中且不越界，文字完整、金额小数位正确。
4. 修改后通过实际样式读回或最新导出确认生效，再预览；出现样式字段清空时检查接口整体替换行为，不能直接归因于客户端缓存或将修复交给用户。
5. 格式差异在用户授权的在线目标内修复后读回核验。平台能力不足或缺少访问权限时，明确列出尚未保留或无法验证的项目及范围；不把本地 XLSX 检查通过当作在线版通过，不报告“格式一致”或“全部完成”。

`check_xlsx.py` 目前检查本地 XLSX 的缓存金额、错误值、禁止文字及可选图片越界，未比较两版的合并和样式，也未覆盖全部图片锚点类型。它的通过结果不能证明在线照片合并、居中、字体或数字格式正确。

## 腾讯文档完整样式写入

本次实测 `set_cell_style` 会重置省略的字段：只传字号/加粗会清空字体、对齐等；只传数字格式会清空底色。修改前保存单元格样式与导出快照，根据保留底色、数字格式和目标字体/对齐生成完整样式块。每次明确传入背景色、字体名/字号/颜色、加粗/斜体/删除线/下划线、水平/垂直对齐、换行及数字格式；不要在全局设置后用只含一个字段的调用覆盖局部。边框另用边框接口设置，再读回核验。按相同完整样式合并连续矩形范围，避免逐格写入。出现错误先从快照恢复受影响样式，再继续。

行高接口虽然声明 pt，本项目现有端点实测按屏幕像素写入。设置 120 后，原生导出的 XLSX 应为 90 pt；以导出结果和在线预览验证，不只看接口说明。只改字体/底色时不重新写行高和照片。

恢复颜色只处理有记录证明由本次助手新增的区域，历史黄色/蓝色保留。无法取得单元格修改人历史时明确说无法确认，不能将文档最后修改人当作标色人。
