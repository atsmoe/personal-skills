# 表格和工具

> **规范版本**：`v2.3.1`（2026-10-09）

## 本项目列映射

工作表名是 `10月份表格`；标题在第1行，表头在第2行。

| 列 | 内容 | 处理 |
|---|---|---|
| A | 序号 | 从最后一条材料序号继续，跳过小结和总计 |
| B | 日期 | `yyyy-mm-dd`；1002表示10月2日，年份从原表或收据核实 |
| C | 材料名称 | 收据为基础，实物可补全或纠正；不要整格丢掉已识别部分 |
| D | 规格 | 可见型号、尺寸、品牌、颜色等；没有依据才空 |
| E | 数量 | 数字，允许重量、长度等小数 |
| F | 单位 | 依据来源填写，不能随意改变计价单位 |
| G | 单价 | 数字，严格沿用两位小数 `0.00` |
| H | 合价 | 数量×单价与票面行金额一致时用 `=E行号*G行号`；只有明确行金额，或有已核实的票面结算尾差时直接保留票面行金额，严格沿用两位小数 `0.00` |
| I | 场景 | 来源未说明则空，不填内部核对文字 |
| J | 照片 | 只嵌实物照片，不能嵌收据；多条明细共用一张照片时纵向合并对应照片格，严格 Contain 居中嵌入，不可溢出该区域边界 |

**全表格局格式**：
以下是保存结果应满足的统一格式；日常追加按新行和有差异的区域应用，已有格式由程序全表核验，无需反复重写全表。
- **全局水平居中与垂直居中**：全表所有单元格（包含表头、明细、小结及总计）统一设置水平居中与垂直居中。
- **全局开启自动换行**：全表单元格强制开启自动换行（wrap text），确保规格型号、材料名称与备注等长文字完整展示。
- **金额两位小数**：单价列（G）与合价/小结/总计列（H）统一使用 `0.00` 格式。
- **字体与边框**：本项目宋体、黑色，正文与表头/汇总 12 pt，标题 16 pt；标题、表头、汇总加粗，正文不加粗。明细和汇总使用黑色细实线边框，新增格也要带边框。
- **底色**：保留历史底色；新明细、汇总默认白底，不自行增加黄色、蓝色或灰底。修改归属必须以修改记录为依据。
- **行高基准**：本项目明细、表头、小结及总计统一为 **90 pt / 在线 120 px**；标题保留实际高度。在线要求至少 120 px；不得沿用旧版 96 pt / 19.2 pt。

新增小结与总计可沿用原表：A:G合并放名称，H放金额，I:J留空。不写任何数量统计。复制格式后检查合并范围是否真的复制成功；部分工具只复制样式而不复制合并关系。

照片合并按采购组定位。例如同一笔采购占第4至6行且共用一张实物照，则合并 `J4:J6`，图片在三行组成的完整区域内居中；不能只把图放在 `J4`，也不能把同一张图重复放进三行。此行号仅为示例，必须从最新表及来源关系确定。同步在线文档时，按 [online-workbook.md](online-workbook.md) 保留相同的合并范围与布局。

## 追加定位示例

同一收据按原顺序逐项录入，不混并项目或重复计算。分别读名称/规格、数量、单价和行金额；不能由总额倒算出一个单价覆盖原图。票面有结算尾差且行金额与整单合计清楚一致时保留票面金额，并在辅助来源记录中说明。

例如旧明细A3:H27，上一天小结第28行，待追加明细第29至44行，则当天小结为 `=SUM(H29:H44)`，累计为 `=SUM(H3:H27,H29:H44)`。这是示例，必须以最新文件的实际位置为准，不能把这些行号写死。若最新状态确认第46行是旧累计且没有新插入内容，下一天可在该位置追加并移到末尾重建累计。多人在线先按 [online-workbook.md](online-workbook.md) 刷新及重定位；本地镜像纳入他人内容，不能按旧例覆盖。

**严格保留用户手动调整的条目**：若用户在先前日期手动调整过条目归属（例如用户在 10.3 增加了集装箱压机、在 10.4 增加了透明玻璃胶等），必须严格原样保留，严禁擅自以收据票面日期或批次为由将条目跨日挪动、删除或回退；小结与累计公式必须纳入口径，不得破坏用户已有小结数值。

用户指定的日期范围就是处理范围。不要因为目录中已有其他天的照片而自动扩展任务。继续同一天时，用当前明细、来源JSON及照片核实是否已录入，避免重复追加。

## 工具选择与 Gemini / agy

- Codex 环境若提供表格技能和 Artifact Tool，遵循该环境的作者工具要求；通过依赖加载工具获取运行时，编辑前做所需操作标记。其渲染器可能不显示嵌入图，需检查导出文件的图片锚点。文件位置以用户路径优先。
- Gemini / agy 无需 Codex MCP 或 Artifact Tool。使用可用的本地 Python（例如 openpyxl + Pillow）或其他可靠 XLSX 编辑工具，并保留现有图片、样式、公式和工作表。使用 `load_workbook` 读原文件，不能从空白表重建用户已有内容；不要用 `data_only=True` 加载后保存，否则会丢失公式。
- openpyxl 可以保留传统浮动图片，但保存时可能不保留某些扩展对象。先检查文件对象：本项目是普通单元格及浮动照片；若其他文件包含 WPS DISPIMG、Excel 单元格图片、宏、签名或不支持的对象，不盲目覆盖，选能保留这些对象的工具。
- 将公式单元格改为票面固定金额后，必须重新读取导出文件，确认旧公式确实移除，而非仅更改缓存显示值。导入导出可能改变既有样式与图片锚点；核对既有内容、公式、合并、样式和图片，遇到工具不能保留的特性时采用保留原始 OOXML 部件的增量补丁，不能用有损重建覆盖原表。
- openpyxl 不计算公式。优先用 Excel、LibreOffice 或可计算公式的工具刷新并核验结果；若环境不提供计算工具，则独立核算新增明细与汇总，并区分公式检查与 Excel 重算验证。不能把空缓存当0，也不能声称已验证缓存。`check_xlsx.py --expect H行号=金额` 用于缓存已刷新时；不传 `--expect` 仍可检查错误单元格和禁止的数量说明。
- 不依赖模型记忆里的软件目录。先找当前机器可用的 `python`、Node 或表格工具。纯清单和导出检查脚本只需要 Python 标准库；接收路径参数，不需要 API 密钥。
- agy 按其加载规则发现带 YAML `name` / `description` 的 SKILL.md。当前机器主副本在 `~/.codex/skills/photo-purchase-ledger`，另有共享 `~/.agents/skills/photo-purchase-ledger`、项目 `.agent/skills/photo-purchase-ledger` 和全局 `~/.gemini/config/skills/photo-purchase-ledger`；Gemini 目录由 `~/.gemini/config/skills.json` 注册。本地 agy 当前实测可从共享 `.agents` 目录加载。更新时同步所有实际存在的副本及项目 ZIP，检查实际发现路径和版本；不以某个旧路径或仅复制成功代替加载验证。业务流程不绑定模型版本。

## 当天识别 JSON 建议

保存到当天 `.work_MMDD`，文件名可为 `data.json`：

```json
{
  "date": "2026-10-03",
  "groups": [
    {
      "receipt": "收据原文件.jpg",
      "photos": ["物品原文件.jpg"],
      "receipt_total": 50,
      "items": [
        {"name": "玻璃胶", "spec": "HC-1000", "quantity": 5, "unit": "条", "unit_price": 10, "amount": 50, "scene": null}
      ]
    }
  ]
}
```

单价、数量缺失时用 `null`，不能填0充数。来源照片索引和原始金额是核对数据，不是已授权新增的表格列。可沿用已存在的当天JSON结构，避免为统一结构改写历史资料。

## 实物照片嵌入与防溢出排版规范

为防止实物照片超出自身单元格、遮挡下行边框或串入相邻行列，必须遵循以下尺寸与锚点约束：

1. **基准尺寸与可用区域**：
   - 必须读取保存文件的实际列宽和行高。默认数字字符宽度为 7 px 的 Excel 工作簿可用 `floor(字符列宽×7+5)` 换算列宽；其他默认字体应校准最大数字字符宽度。不能固定采用 290 px。
   - 本项目 90 pt 对应 120 px，上下各留 8 px 后单行照片可用高度为 104 px。合并区域按其中每一行的有效行高累加；如果行高或列宽改变，重新计算受影响图片的尺寸和偏移。
   - 全表采购明细使用同一个固定行高：沿用用户已确认的统一基准，本项目为 90 pt / 120 px；其他项目无基准时先根据实际布局选取统一值，不能把平台像素值当作 Excel 磅数。无图行和照片合并区域内的明细行也不能变矮；多条明细合并单张照片时，区域高度为明细行数乘以统一行高，不通过单独拉高某一行来容纳图片。本项目表头、小结与总计同样为 90 pt；其他项目按各自样式设置。
   - 必须预留安全内边距（Padding）：上下各预留至少 8 px（约 76,200 EMU），左右各预留至少 14 px（约 133,350 EMU）。
   - 可用最大宽高：
     - $W_{\text{avail}} = W_{\text{col}} - 2 \times \text{Padding}_X$
     - $H_{\text{avail}} = H_{\text{cell}} - 2 \times \text{Padding}_Y$

2. **等比缩放计算（Contain 模式）**：
   - 根据原始实物照片物理宽高 $(W_{\text{orig}}, H_{\text{orig}})$，缩放比例严格取：
     $$\text{scale} = \min\left(\frac{W_{\text{avail}}}{W_{\text{orig}}}, \frac{H_{\text{avail}}}{H_{\text{orig}}}\right)$$
   - 图片最终放置尺寸：$cx = \text{round}(W_{\text{orig}} \times \text{scale})$，$cy = \text{round}(H_{\text{orig}} \times \text{scale})$。严禁使用固定像素高度导致图片冲破行高限制。

3. **双向几何居中对齐**：
   - 垂直与水平偏移量严格居中计算：
     $$\text{rowOff} = \text{round}\left(\frac{H_{\text{cell}} - cy}{2}\right)$$
     $$\text{colOff} = \text{round}\left(\frac{W_{\text{col}} - cx}{2}\right)$$
   - 确保满足防溢出硬性约束：$(\text{rowOff} + cy) \le H_{\text{cell}}$ 且 $(\text{colOff} + cx) \le W_{\text{col}}$。

4. **自动化核验**：
   - 保存后使用自动化脚本遍历 `xl/drawings/drawing1.xml` 中的每个 `oneCellAnchor` / `twoCellAnchor`，核对每个图片的延伸范围是否完全收敛在对应行与列之内，越界数必须严格为 0。

## 保留原始工作簿包

字体和边框调整应只改授权样式，保留公式及其缓存、合并、图片原始字节与锚点、关系、列宽和行高。若作者工具导出不能保留原始对象，用作者工具生成所需样式，再将对应样式和单元格样式引用增量转入原始 OOXML 包；不要用有损重建覆盖原表。处理 XML 保留原始命名空间声明，包括 `mc:Ignorable` 引用的全部前缀。写 ZIP 时复制 ZipInfo，避免修改正在读取的源条目。保存后核验仅授权部件变化，再用 Excel 正常打开确认没有修复提示。
