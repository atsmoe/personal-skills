# 采购表低消耗执行计划

日期：2026-10-09。状态：计划，尚未实施。

## 目标与范围

落实固定执行脚本、限制模型回传、图片增量核对和采购任务工具收敛。日常模型工作尽量随新增来源增长，全表扫描、金额计算和格式检查由本地程序完成。主表与格式按当前项目确定，保留他人增补、历史底色及日期归属，本地正式表写前备份。

现有 2.4.0 已有增量原则、三个观察入口、可迁移参数及输入输出保护。以它们为基础实现后续执行管线；本次可迁移与安全更新不表示下面的自动写入/接续计划已经完成。

## 第一阶段：固定执行脚本（第3项）

交付一个分阶段运行入口，内部复用 inventory、ledger_context、check_xlsx，并整理腾讯传输、写入、照片布局和 Excel 验收模块。

固定流程：

1. 获取在线最新状态和本次日期来源，生成基线与变化摘要。
2. 交给模型本次需识别的证据，保存识别结果及用户更正。
3. 生成差异写入计划：待补采购、当前目标位置、金额、合并、照片与样式。
4. 写前刷新目标区域，重新匹配缺项。在线已存在的采购不重复追加；插删行后重新定位。
5. 局部写入，记录已完成步骤，紧接读回。只有验证过的幂等操作可以自动重试；结果不明的插行或插图先检查是否成功。
6. 从在线最新导出更新本地，自动处理已知的导出照片几何问题；Excel 正常打开、重算，核验金额、历史内容、照片、行高和格式后保存正式文件。

并发冲突发生时保留他人修改，重新计算受影响的写入计划。持续无法定位的区域暂停写入并报告，继续独立核对；不回滚整张在线表。凭据由原授权文件读取，不写入日志、参数摘要或技能包。

## 第二阶段：限制模型回传（第4项）

- 每个阶段默认摘要不超过 2,000 字符，常规摘要硬上限 5,000 字符；异常最多展示10项，超出内容写文件并返回路径与省略数。
- 全量表格、样式、工具响应及日志落盘。模型只接收金额、变化区域、待识别来源和影响决策的异常。
- 禁止打印全部工具定义、整表 JSON、图片 base64。模型只查询已知任务所需能力；技能入口保持简短，详细参考按需加载。
- 不在同一次执行中反复读取同一技能、工具说明或源码。运行入口及阶段摘要支持中断后从工作记录接续。
- 不重复扩大已经通过的检查；新修改、失败或尚未解决的问题触发对应范围重验。

字符上限约束的是常规回传，必要的新证据按明确区域另取，不以截断隐藏问题或宣称验收通过。

## 第三阶段：图片增量与工具收敛（第5项）

- 来源记录保存原图哈希、CreationTime、采购组、核实字段、表内匹配和验收版本。只有曾核实、哈希一致且当前对应内容与照片关系未变的记录才能复用。
- 新增、改变、未核实或用户指定重查的来源进入模型核对。插删行先重定位，结构变化本身不触发全月重识图。
- 新采购按组看概览；涉及金额和单位必须读取清晰原图或疑点裁剪。原图保留，裁剪存辅助目录，低清概览不作为定金额依据。
- 在线变化先做程序差异检测，只扩展到有变化的采购组。其他人新增的采购保留，并列出本次范围内无本地来源的条目。
- 只预览新增或实际受影响的照片区域及末尾汇总，保留在线独立读回与必要界面预览。
- 检查当前客户端是否支持项目/任务级 MCP 限制及工具筛选。支持时采购任务仅启用必要的腾讯表格、导出和本地表格能力；缺少该作用域时列明限制，采用固定脚本路由，先给出全局连接调整建议，不在本计划阶段变更配置。

## 第四阶段：验收、发布与效果对比

先使用备份及保存的在线快照做离线演练：重复执行不重复采购、跨日补单、来源图片改变、他人新增条目、插删行及部分操作成功后的恢复。全量导出导致照片布局变化时，程序修复但保留原始图片内容。

随后用下一次真实新增采购验证在线及本地：金额正确，未知字段留空，历史内容与他人采购保留，照片对应及合并正确，新增格带边框，满足当前项目的行高及统一格式基准，Excel打开无需修复。

实现完成后更新技能说明、同步当前实际副本和ZIP，并用本地agy实际加载验证；不以复制成功代替可用性验证。

正常日常更新的初步目标：模型处理控制在约10—15轮、常规工具回传文字总量不超过40,000字符。这是优化目标，不是自动停止完成工作的硬限额；故障处理单独记录原因。

选取可比较的先前任务作为基线，记录新任务的模型、推理设置、来源复杂度、模型轮次、回传字符、未缓存输入和输出token。额度比例受账号其他任务影响，仅作辅助观察；不保证固定节省比例。工程开发成本与日常运行成本分开记录。

完成顺序：固定脚本 → 回传限制 → 图片增量与工具范围 → 离线验收 → 下一次真实更新 → 技能发布与效果报告。
